# FloatNote Windows / macOS 桌面版设计

v1 · 2026-11-23 · 已批准实施

## 1. 产品目标与技术决策

用户在编辑器、浏览器或多个 agent 会话之间工作时，可以抬眼读便签、按键收起、双击补一句，然后继续手头工作。浮窗的识别特征是透明背景上的描边文字。看笔记、编辑笔记和长期驻留三个场景共同决定选型。

建议采用 **Tauri 2 + TypeScript + 原生 HTML/CSS**。Windows 使用 WebView2，macOS 使用系统 WKWebView。阅读态只创建一个小窗口，编辑时原位切换输入框。外观、热键、历史共用一个按需创建的普通工具窗口，关闭即销毁。此规模的界面可以用 DOM 和 CSS 实现，发行包中无需携带 Python、Qt 或完整 Chromium。

| 备选 | 对当前项目的价值 | 取舍 |
| --- | --- | --- |
| Tauri 2 | 桌面壳提供窗口和托盘，有官方热键插件，文字布局可用 CSS 实现 | 首选。两种 WebView 的透明区域、鼠标和焦点行为必须用发布构建验证 |
| 现有 PySide6 | Windows 版本可作为交互与性能对照，已有数据读写测试 | 保留为验证基线和回退版本。继续沿用将保留 Python/Qt 分发与原生适配成本 |
| Electron | 可共享 Chromium 渲染和大量桌面接口 | 若 Tauri 无法满足核心手感，再评估实包和同机内存。它会随应用分发 Chromium 和 Node.js |

首期拟覆盖 Windows 11 x64、macOS Apple Silicon 与 Intel。Windows 10 x64 作为候选兼容目标，发布时按实际测试标注；macOS 最低版本根据锁定的依赖、构建目标和可验证设备确定。发布范围为 GitHub 下载，初期测试包与可公开分发的签名版本分开标识。Mac App Store、Linux、跨设备同步、多便签和点击穿透均不进入本次验收。

技术依据见 [Tauri 的系统 WebView](https://v2.tauri.app/reference/webview-versions/)、[窗口配置](https://v2.tauri.app/reference/config/)、[全局快捷键](https://v2.tauri.app/plugin/global-shortcut/) 和 [系统托盘](https://v2.tauri.app/learn/system-tray/)。

## 2. 用户可观察的行为

| 场景 | 设计 |
| --- | --- |
| 启动、阅读 | 单实例。恢复上次外观和位置，首开靠近主屏右上角。桌面普通应用窗口上方只显示文字和描边。双开时唤回已有便签。 |
| 从其他应用按热键 | 显示或隐藏。显示后原应用仍接收键盘输入。隐藏中的便签通过托盘或菜单栏也能找回。 |
| 拖动与双击 | 在字上、行间或便签边距内均可操作。轻微手抖仍可双击，超过拖动阈值才启动拖动。窗口矩形外的鼠标操作交给下层应用。 |
| 编辑 | 双击在点击位置附近放置光标，进入有底色的编辑态。中文输入法组字期间按 Enter 或 Esc 由输入法处理。普通编辑时 Esc、Ctrl+Enter、点击其他窗口完成保存，macOS 另支持 Cmd+Enter。 |
| 长笔记 | 按宽度换行，高度随正文增长，最大为所在显示器工作区高度的 80%。超出后内部滚动，编辑时照样能到达最后一行。 |
| 外观与多屏 | 沿用字号、文字颜色、自动对比色描边、透明度和宽度。透明度作用于阅读文字。按逻辑尺寸保存，恢复时检查窗口是否仍在可见工作区；拔掉显示器后能通过菜单重置位置。 |
| 右键与托盘 | 便签右键可编辑、隐藏、打开样式、快捷键、历史、重置位置及退出。Windows 托盘和 macOS 菜单栏提供显示/隐藏、设置、历史、重启、退出。优先遵循各端惯例，所有功能可通过明示菜单项到达。 |
| 热键冲突 | Windows 默认 Win+Shift+Q；macOS 拟用 Control+Option+N，避开系统注销组合键。注册失败时指出冲突，保留可用旧键与菜单入口。修改成功后重启仍有效。 |

**焦点验收例**　在编辑器里连续输入“甲”，按热键显示便签，再输入“乙”；“乙”必须仍出现在编辑器。随后双击便签的行间，用拼音输入“明天跟进”，选词后点回编辑器。再打开便签能读到完整汉字，历史中只出现这次完成的修改。

## 3. 组件边界与运行流程

| 组件 | 职责 |
| --- | --- |
| 浮窗前端 | 阅读、编辑、中文输入、拖动意图、测量内容高度。草稿仅在编辑期间驻留内存。 |
| 工具窗口前端 | 外观预览、按键录入、历史日期范围、增删记录和复制。只展示用户笔记的纯文本。 |
| Rust 桌面层 | 窗口创建和销毁、单实例、非激活显示、置顶、全局热键、托盘、多屏定位和应用退出。平台差异集中在这里。 |
| Rust 存储层 | 选择用户数据目录、读取和校验旧格式、原子写入、Git 检查点和历史查询。它拥有持久状态并串行处理对同一文件的更新。 |
| 发布构建 | 在各自系统构建 release 产物，锁定 npm/Cargo 依赖。记录目标架构、版本、系统运行时条件、签名状态与产物大小。 |

浮窗状态为「隐藏」「阅读」「编辑」「保存中」。热键、托盘、关闭、重启共享同一条退出编辑流程。正文写入成功后才隐藏或退出；写盘失败则保留草稿与重试入口。历史写入失败时单独提示“正文已保存，历史记录失败”。并发的失焦与热键复用同一次保存，防止重复提交或早于落盘退出。系统异常终止时只保证已完成保存的正文。

前端通过有限的命令读取快照、保存正文、修改外观、注册热键、查询历史或请求窗口动作。外观修改只写变化字段，移动窗口只更新位置，避免设置覆盖新坐标。Git 与文件路径由后端管理；笔记正文始终按纯文本渲染。阅读态无后台定时刷新，位置只在移动结束后合并写入，Git 查询在工作线程运行。

## 4. 数据与升级

| 数据 | 升级约定 |
| --- | --- |
| `notes.txt` | UTF-8 纯文本，兼容旧版 BOM、换行和空笔记。采用同目录临时文件加原子替换，保留最后一次成功写入。 |
| `config.json` | 沿用位置、字号、颜色、宽度、透明度和描边。旧 Windows 虚拟键码转成跨平台组合键，按值迁移，未知键提示重新绑定。损坏的配置另存副本后恢复默认。 |
| `notes-history/` | 继续读取已有本地 Git 仓库，保留提交、时间戳与按时间范围查看增删的能力。新旧历史连续。Git 为历史功能的可选系统依赖，正文可以独立保存。 |

全新安装默认写入当前用户的应用数据目录。Windows 便携版在可执行文件旁发现一套旧数据时，可继续原地使用；遇到只读目录时提示选择可写位置。通过安装程序升级、从源码目录迁移或从 Windows 换到 Mac 时，由用户明确选择旧数据目录，新版复制完整数据集到用户目录。源文件保留。目标已有笔记时先展示冲突，不静默合并或覆盖。实现可将这一步放在设置中的“导入旧版数据”，导入成功前继续使用原目录。测试和原型使用临时数据目录。

回退时可用旧程序与升级前的数据副本继续工作。迁移验收使用真实格式的测试副本，比较正文内容、历史提交 ID 和时间范围，并覆盖只读目录、已有数据、损坏配置、Git 缺失与热键冲突。

## 5. 轻量指标与发行物

当前 Windows 旧版基线来自现有便携 ZIP：下载 **36.8 MiB**，包内文件解压合计 **93.2 MiB**。旧版常驻内存、启动时间和新版数字均待测。以下数字是本设计建议的目标，供审阅时调整。

| 维度 | 建议目标与测法 |
| --- | --- |
| 下载和占用 | Windows x64 release 安装包及每种 Mac 架构的 DMG 各自争取 ≤15 MiB。分别报告下载体积、安装占用。Windows 已有 WebView2 与需要下载运行时的首次安装分开记录。 |
| 常驻资源 | 同一台 Windows 机器、相同笔记，在启动静置 60 秒、隐藏 60 秒、打开并关闭历史窗口后三个状态测量旧版和新版。包含 WebView 子进程，记录私有内存和空闲 CPU。Mac 单独报告进程树内存口径。目标为空闲无持续 CPU 活动；Windows 私有内存若高于旧版 25% 以上，先回到选型审阅。 |
| 启动与操作 | release 构建测 5 次首次可见并可操作时间，区分首次安装和日常启动。日常启动目标中位数 ≤1.5 秒；热键显示/隐藏目标 ≤150 毫秒，连续 20 次无漏触发、双切换或抢焦点。 |
| 产物 | Windows x64 安装包和可独立取用的 EXE（依赖系统 WebView2），macOS 两种架构分别生成 DMG。签名、公证和系统安全提示按实际发布状态说明。 |

系统 WebView 的复用可以缩小应用下载包，常驻内存与交互延迟须由这套测量决定。在原型上发现超预算时，先给出同机数据、可优化项和代价，再由负责人决定是否接受。

## 6. 实施顺序与验收门槛

1. **验证窗口行为。** 在隔离分支和临时数据目录只做透明文字、拖动、双击中文编辑、全局唤出和托盘。Windows 与 Mac 真机各完成第 2 节的焦点用例，再测空白区域鼠标命中、多屏、显隐和基础资源。若核心体验需要长期依赖未公开的平台接口，提交原因、版本影响和替代方式，请负责人重新选型。
2. **迁移核心功能。** 阶段一通过后接入存储、旧数据导入、设置、历史和生命周期；用自动化验证迁移、并发保存、热键失败恢复、磁盘错误和同一内容不重复提交。
3. **完成发行验证。** 在 Windows x64 和两种 Mac 架构分别构建，执行可覆盖的自动化测试。在有设备的系统做安装、启动、编辑、退出、重启、升级和恢复测试，记录系统与芯片。CI 编译成功和真机交互通过分别标注。
4. **发布 0.3.0。** 按负责人授权推送重构分支，在 GitHub Actions 上完成三种架构构建与启动验证。用对应提交的产物创建 Release，附下载链接、校验值与签名状态。

现有 Python 版本用于同机对照。开发与发布验收使用隔离数据目录和复制的历史仓库。
